الدليل التقني والتعليمي الشامل للنظام

الإصدار 1.0 - التوثيق الرسمي لدورة العمل وهيكلة البيانات

1. نظرة عامة على النظام (System Overview)

نظام WaterApp هو نظام تخطيط موارد المؤسسات (ERP) متكامل ومخصص حصرياً لإدارة مصانع وشركات توزيع المياه. يدمج النظام بين عمليات الكاشير السريعة (POS)، إدارة حركة الأسطول، والمحاسبة المالية المزدوجة.

  • واجهة المستخدم (Frontend): مطورة بتقنية Next.js و React لضمان سرعة التصفح.
  • قاعدة البيانات (Backend): تعتمد على Supabase (PostgreSQL) لضمان موثوقية وأمان البيانات.
  • التصميم (Theme): يعتمد هوية "Aqua Glassmorphism" الزجاجية المائية.

2. هيكلة الواجهات الأمامية (Frontend Architecture)

يتكون النظام من عدة وحدات برمجية (Modules) تعمل بشكل مستقل ومترابط:

  • app/pos: شاشة الكاشير السريعة وإدارة الورديات (Shifts) وحساب العجز والزيادة.
  • app/invoices: لوحة إدارة مبيعات الجملة والمشتريات.
  • app/inventory: متابعة حركة المخزون وتكلفة البضاعة المباعة (COGS).
  • app/fleet_operations: إدارة أسطول التوزيع ورحلات المناديب والمصروفات الخاصة بكل سيارة.
  • app/journal: القيود المحاسبية الآلية واليدوية لدفتر الأستاذ.

3. هيكل قاعدة البيانات (Backend Schema)

أ. مجموعة الحسابات والموارد

  • accounts: الدليل المحاسبي الشجري لجميع أصول وخصوم وإيرادات الشركة.
  • partners: سجل العملاء، الموردين، والمناديب.

ب. مجموعة المبيعات والعمليات

  • pos_shifts: الورديات المفتوحة والمغلقة للكاشير والمناديب.
  • invoices: الفواتير (نقدية/آجلة) المرتبطة بضريبة القيمة المضافة ZATCA.
  • receipt_vouchers و payment_vouchers: سندات القبض والصرف وتوجيهها المحاسبي.

ج. مجموعة المخزون (Inventory)

  • inventory_transactions: السجل التاريخي لكل حبة تخرج أو تدخل (بمثابة كارت الصنف).
  • warehouse_inventory: الرصيد التراكمي المحدث لحظياً لكل مستودع وسيارة.

4. الدورات المستندية (Documentary Workflows)

📊 أولاً: دورة المبيعات ونقاط البيع (POS)

مسار العمل اليومي للمندوب أو البائع:

1. فتح وردية الكاشير
➔
2. استلام العهدة (نقد/فوارغ)
➔
3. إصدار فواتير البيع


4. توليد سندات القبض الآلية
➔
5. خصم المخزون اللحظي
➔
6. إغلاق الوردية وحساب العجز

قواعد النظام: يمنع النظام تماماً أي عملية بيع دون وجود وردية مفتوحة. كما يولد النظام قيداً محاسبياً فورياً عند الدفع لترحيل المبيعات.

💧 ثانياً: دورة عهدة الفوارغ (Returnable Bottles)

  • الأصناف المعلمة كفوارغ is_returnable_bottle = true تخضع لجرد صارم.
  • عند البيع، يجب على النظام تسجيل عدد الفوارغ المستلمة من العميل.
  • عند الإغلاق، يطابق النظام بين (عدد العبوات المباعة) و (عدد الفوارغ المسترجعة) ويحسب العجز فوراً.

5. الدوال المحاسبية والإجراءات المخزنة (RPCs)

قاعدة البيانات مزودة بـ "عقل محاسبي" يعمل في الخلفية لمعالجة الأرقام:

  • post_invoices_bulk(): دالة تقوم بتحويل أي فاتورة يتم حفظها إلى قيود مزدوجة (Debit/Credit) لتسميعها في المركز المالي وحساب ضريبة القيمة المضافة تلقائياً.
  • auto_create_pos_receipt(): دالة تولد سندات القبض فوراً عند قيام العميل بالدفع في شاشة الكاشير لمنع نسيان تحصيل المبالغ.
  • approve_inventory_transaction(): دالة تسجل خروج البضاعة من المخزن، وتقوم بإنشاء قيد محاسبي يخصم (تكلفة البضاعة المباعة COGS) ويرحلها.

6. المحفزات الآلية (Database Triggers)

  • update_partner_balance_on_journal: محفز آلي يراقب القيود المحاسبية، وبمجرد إدراج أي مديونية أو دفعة، يقوم بتحديث رصيد العميل current_balance لضمان أن كشف الحساب دائماً محدث بالهللة.
  • set_invoice_payment_status: يراقب سندات القبض ويقوم بتحويل حالة الفاتورة من (غير مدفوعة) إلى (مدفوعة) فور تغطية المبلغ بالكامل.
